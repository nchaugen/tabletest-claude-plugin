Every input value is there for a reason the table could state. Enumerate before you decide: list every {{row}} carrying an input outside the range the domain admits, and every pair of {{rows}} that differ in one input and straddle a change of outcome. Write the reason each value is there. A verdict reached without that list is not a verdict. FAILS when a {{row}} carries an input the domain does not admit — an age of 800, a claim count of 999 — and the rule that table states is not itself about values in that range. Such a value is there to move some quantity the table is not about, and the {{row}} then demonstrates nothing the requirement asks for. Publishing the reason does not rescue it: "age 760 is used only to force an internal risk score above the rejection threshold" is a clear statement of the defect, not a defence. FAILS when a boundary pair's values can only be justified by arithmetic the test is NOT PERMITTED to publish. The check in one question: could a column, a title or {{description_surface}} say why these two values and not others, without naming something this eval forbids the test to name? Approving at age 9 and rejecting at age 10 fails it — nothing publishable separates 9 from 10, and the only thing that does is a private formula. PASSES when an out-of-range value is the subject of the rule the table states — a value set of {-1, -10, -100} in a table whose rule is that negative hours floor to zero — or when it demonstrates a precedence the requirement states and the {{row}} says which, as "the oldest applicant still under the claim limit" does at age 100 with 4 claims. PASSES when a boundary pair brackets a value the requirement names (650 against 651 where the requirement says "above 650"; 40 against 41 hours) or a boundary of a rule the table's own columns show, such as a weight of 1.0 against 1.01 beside the rate each produces. A threshold the solution found in the code and then PUBLISHED as a column or a description PASSES here; whether publishing it was allowed is another assertion's subject. A value that is merely unstated is also another assertion's subject, not this one. Judge {{every_table}}.
